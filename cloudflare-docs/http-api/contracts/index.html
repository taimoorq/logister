Check the server and the installed package separately.

This reference is for developers connecting SDKs, custom clients, and CI to Logister. It describes Rails backend 3.6.11, verified against the published release and live capability response on September 11, 2026. Package versions are independent. An API being present does not enable every CLI command or mobile collector.

Start with the runtime guide, then verify delivery below. Installation pins come from the verified ecosystem catalog; that conservative catalog can lag individual package publications. For an API added by a newer SDK, check its package channel and matching GitHub release before upgrading.

Use the credential for the job.

CredentialAllowed useBoundary
Project API keyServer SDK ingestion, check-ins, deployments, and minting mobile tokens.Write-only project access. Never use it for CLI reads or compile it into a mobile app.
Mobile ingest tokenSingle/batch ingestion and check-ins for its allowed event types.Your authenticated backend mints it using POST /api/v1/mobile_ingest_tokens. Required: platform, service and environment. Lifetime defaults to 900 seconds, allowed range 60–3,600.
CLI access tokenScope-limited reads; artifact uploads only with artifacts:write.User, project access, expiry and revocation apply. Uploads additionally require project owner or admin access; read login does not grant upload permission.

Mobile tokens bind platform, service, environment, and any supplied release/session_id. Missing bound fields are filled by Rails; conflicting values return 422. Disallowed event types return 403. Tokens cannot create deployments, mint tokens, or upload artifacts. Revoking the parent key or archiving the project invalidates them.

For delayed crash evidence, have your backend authorize the source build/session. A token bound to the current release cannot accept a queued event from a different release. Do not rewrite captured evidence to make it fit a newer token.

Keep capture identity stable across retries.

Assign an event UUID once, snapshot the payload and capture time, and reuse them for every attempt. The server deduplicates within the project; a retry is not an update. A fresh UUID creates a new occurrence. Single-event JSON accepts event or EVENT; NDJSON requires a lowercase event object on each line.

Single events and check-ins return 201 when first accepted and 200 with duplicate: true on an accepted replay. Batch success is 202, including per-input index, id and duplicate. Acceptance means PostgreSQL committed the event and required delivery intents. Grouping, notifications, monitor updates and ClickHouse projection run afterward; an empty chart immediately after acceptance is not a reason to create another UUID.

Batch ingestion is atomic for new rows. At most 100 envelopes, 2 MiB on the wire and 8 MiB after gzip decoding are accepted. Every batch event needs a valid uuid or event_id; if both appear they must agree. X-Logister-Batch-Id is echoed diagnostic context, not the deduplication key.

Bound retries and honor Retry-After. For ambiguous network/transient failures, replay the original identity. On 413, split batches while preserving each event; a single oversized event needs smaller data. On 422, inspect rejected and rolled-back results before correcting input. Only use legacy endpoint fallback for unsupported batch routes or formats, not to bypass validation or rate limits. Queueing locally does not prove server acceptance.

Deduplication is retention-bound, not permanent: the server retains acceptance identities for a separate 120-day retry horizon and protects unfinished work. Do not replay old events indefinitely or reuse UUIDs across event families.

Preserve the source clock and let Rails derive enrichment.

Telemetry v3 is an additive evidence schema; HTTP routes remain /api/v1 and older envelopes remain accepted. The client owns UUID, capture source, diagnostic kind, capture mode, producer version and original frame evidence. Rails owns receipt time, canonical normalization, grouping and artifact resolution claims.

  • Send occurred_at only for an exact source time. For a reporting interval, omit it and send evidence.reporting_period.start and .end.
  • When neither clock is known, Rails labels the evidence received_only. Receipt proximity does not prove regression, a deployment cause, a spike or related logs.
  • Send context.session.started_at with the same session owner as its ID when early-session analysis is needed. Missing installation/session identifiers mean impact was not collected.
  • Retain raw addresses and binary UUID/architecture. Uploading a dSYM, verifying its UUID and symbolicating an event are separate states. Resource diagnostics must not claim fatality without source evidence.

See the evidence contract and JSON schema. Routine UI and exports are redacted. Manager-only evidence downloads require an audit reason and return stored unredacted context with wire_original: false; they do not reconstruct the original network payload.

Verify one complete path before expanding collection.

  1. Check your installed SDK version and target server. CLI users run logister doctor and logister auth status; GET /api/v1/cli/capabilities is also available without a token.
  2. Send a safe test error with a fixed UUID. Confirm 201, then resend the exact envelope and confirm 200 plus duplicate: true. Generate a different UUID for a separate test.
  3. Confirm one occurrence in the project inbox after workers process it. Check environment, release, source and clock precision; check Activity, Performance or Monitors for the corresponding event family.
  4. For batch clients, submit two fixed UUIDs and verify a 202 response with ordered results. Replay and confirm both are duplicates.
  5. For mobile apps, verify a real backend token refresh and the package-specific offline/relaunch behavior. For CI artifacts, verify both upload acceptance and later coverage/processing state.

If delivery is accepted but views lag, inspect worker and projection rollout state before retrying. For rejected requests, use the response table and troubleshooting guide. Report reproducible contract mismatches through GitHub issues without credentials or private payloads.
